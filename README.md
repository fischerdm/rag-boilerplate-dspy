# rag-boilerplate-dspy

A small project for learning DSPy syntax by classifying Reuters-21578 articles into 7 topics
(`earn`, `acq`, `crude`, `money-fx`, `grain`, `trade`, `interest`).

Motivation: in [fastapi-rag-boilerplate](https://github.com/fischerdm/fastapi-rag-boilerplate)
inferring these labels with an LLM turned out to be hard. Here we check how far DSPy's
modules and optimizers get.

## Setup

```bash
uv sync
cp .env.example .env   # add your API key
```

## Steps

| Script | DSPy concept |
|---|---|
| `common.py` | `dspy.Example`, `dspy.Signature` with a `Literal` output, metric, `dspy.configure` |
| `01_baseline.py` | `dspy.Predict`, `dspy.inspect_history`, `dspy.Evaluate` |
| `02_chain_of_thought.py` | `dspy.ChainOfThought` (adds a `reasoning` field) |
| `03_optimize.py` | `dspy.BootstrapFewShot` / `dspy.MIPROv2`, `save` / `load` |

```bash
uv run 01_baseline.py
```

Data: single-label articles only, sampled per topic (8 per topic for training,
up to 15 per topic for evaluation) since a uniform sample is ~80% `earn`/`acq`.
LM calls are cached by DSPy, so re-running a script is free.

Building a golden dataset is left for later.

## Good to know

### DSPy and LiteLLM
- DSPy uses the open-source Python library LiteLLM that lets you call many LLM providers through one interface.
- The provider/model format (e.g. anthropic/claude-haiku-5-5) and which environment variable holds the key (ANTHROPIC_API_KEY, OPENAI_API_KEY) both come from LiteLLM, not from DSPy.
- That's why switching models only means changing the DSPY_MODEL string.
- DSPy builds the prompt from your signature and hands it to LiteLLM, which sends it to the right provider. DSPy never has to deal with each provider's details itself.

### DSPy input and output fields
`text: str = dspy.InputField()`: <br>
The field is one input value that DSPy puts into the prompt, and DSPy builds the full prompt from the whole signature.

`topic: Literal[tuple(TOPICS)] = dspy.OutputField()`: <br>
Flags this variable as the output field to be generated by the AI. It restricts both the language model and the code from outputting arbitrary text, forcing it to choose exactly one of the values specified within the brackets. `Literal[tuple(TOPICS)]` is the same as writing `Literal["earn", "acq", ...]`, i.e. 7 allowed values. With a list, `Literal[TOPICS]` would mean one single allowed value, the list itself.
